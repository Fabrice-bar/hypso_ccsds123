# HYPSO custom weight initialization — Figure 4-21

This runs the experiment described in CCSDS 120.2-G-2, section 4.2.6,
Figures 4-20 and 4-21, with your five HYPSO captures. The main plot is the
**average percentage reduction in compressed data rate versus test-image height**.

## Install and run

Extract the ZIP at the root of `ccsds123_issue_2_verification_model` (or your
`hypso_ccsds123` checkout). It adds `tools/weight_init/` and does not edit the codec.
Keep the three Python files together. Use your existing working environment;
additional plotting/NetCDF dependencies are `matplotlib` and `netCDF4`.
The reference model also requires `numpy`, `bitarray` and `psutil`.

From the repository root, with the original five capture filenames under `data`:

```bash
python tools/weight_init/weight_init_study.py --input-dir data --full-width --heights 16 64 256 --locations 2 --workers 2 --output results/fig421
```

Windows PowerShell, without activating the environment:

```powershell
.\.venv\Scripts\python.exe tools/weight_init/weight_init_study.py --input-dir data --full-width --heights 16 64 256 --locations 2 --workers 2 --output results/fig421
```

The default scenes are Lisbon, Bangladesh, Santarem, Doha and Finnmark.
Native dimensions are read separately from each file. All native bands are retained.
The default workload is:

**5 images × 3 heights × 2 locations × 2 methods = 60 test compressions,
plus 10 training compressions.**

Append `--dry-run` to inspect the workload, coordinates and memory checks without
performing compression or writing results. Repeat an unchanged command to resume.

## Training and testing

For each capture and each selected location:

1. Losslessly compress 16 training rows with default initialization and
   `nu_min=-1`. Save the predictor's final weight vectors; discard training output.
2. Extract the test strip **immediately below** that training strip, using identical
   columns and spectral bands. Training and test samples do not overlap.
3. Compress that same test strip with default initialization at `nu_min=-1`, then
   with the quantized trained weights at `nu_min=3`.
4. Repeat for each requested test height. These test strips are nested prefixes
   with a common start row. Reuse the training weights across heights.
5. Compute the percentage rate reduction for each pair and average over locations,
   separately for each image and height.

Only the weight vectors are transferred. Predictor spatial history, adaptation
position and entropy-coder state start afresh for every test compression.
Each test remains independently decodable when its custom table is included.

`--full-width` uses every native column; the test height remains the swept variable.
This follows the full-x/full-z strip geometry in Figure 4-20.

Automatic training start rows are evenly spread from 0 to
`native_height - train_height - largest_test_height`. One location is centred.
For a 956-row capture and the default heights, the two training strips are
rows `[0:16)` and `[684:700)`, with tests beginning at rows 16 and 700.
Indices are zero-based and the end row is excluded.
`plan.csv` records the exact crop for every job.

For selected locations, replace `--locations 2` with e.g. `--train-rows 100 500`.
The same explicit row indices must fit every selected capture. If different
locations overlap, the script reports that; averages are descriptive, not
independent statistical replicates. Heights at one location are intentionally nested.

## Parameters

| Parameter | Default |
|---|---:|
| Fidelity | Lossless, A=0 |
| Entropy coder | Sample-adaptive |
| Prediction bands P | 3 |
| Prediction mode | Full |
| Local sum | Wide neighbour-oriented |
| Dynamic range D | 16 bits, unsigned integer DN |
| Register size R | 64 |
| Weight resolution Omega | 19 |
| Initialization resolution Q | floor(Omega/2) = 9 |
| Training/default nu_min | -1 |
| Custom nu_min | 3 |
| nu_max | 3 |
| t_inc | 64 |
| Weight exponent offsets | All zero |
| Sample-representative damping/offset | Zero; optional structure omitted |
| Sample-adaptive Umax, gamma*, gamma0, K | 18, 6, 1, 3 |

The Green Book uses the sample-adaptive coder for this experiment, including
the custom weight-table overhead. Its Annex C selects prediction mode and wide
sum type by instrument. HYPSO is not listed there; full mode and wide-neighbour
sums are the general-case choice used here. These are backwards-compatible
predictor settings. The output is still generated by the Issue-2 verification model.

The experiment-specific `nu_max=3` overrides Annex C's general default. At D=16,
`min(nu_max+D+1,19)=19`, giving Q=9. The baseline and custom cases intentionally
also differ in nu_min, as Figure 4-21 specifies: the result is not an isolated
effect of changing initialization alone.

The script accepts changes to P, sum type, prediction mode, Omega, Q, nu_min,
nu_max and t_inc. Changing the Figure 4-21 settings makes a HYPSO variant of the
experiment; the actual settings are recorded. This driver is lossless and uses
the sample-adaptive coder throughout.

Original L1A integer DN are used without calibration, spectral resampling, noise
addition or automatic wavelength cuts. Keeping the same band ordering and all
bands in each training/test pair avoids changing the predictor's spectral context.
This is a compression-rate study, not a calibrated spectral-quality study.

## Rate accounting and outputs

For location j and height H:

`reduction_j(H) = 100 * (default_bits_j(H) - custom_bits_j(H)) / default_bits_j(H)`

The primary plotted value is the arithmetic mean of these percentages across
locations. Larger values are better. Negative results are retained.
The book states that results are averaged but does not specify the number of
locations, exact positions, or detailed averaging convention. Two evenly spaced
locations and the mean of paired percentages are explicit pilot choices here.
The ratio of mean rates is also saved for comparison.

Counted bits include the complete Issue-2 header, embedded custom weights,
entropy payload and required output-word padding. Training compression size is
excluded from the test-rate comparison, as in the book. No side information is
silently made free. With 120 bands, P=3, full mode and Q=9, the custom table has
714 coefficients, 6426 data bits and 6432 bits after byte padding (804 bytes).

Outputs:

- `fig421_rate_reduction.png` and `.pdf`: one averaged curve per capture.
- `rates_by_height.png` and `.pdf`: average default/custom bits per sample.
- `fig421_summary.csv`: means, range across locations, and ratio of mean rates.
- `comparisons.csv`: every paired percentage reduction.
- `results.csv` and `training_results.csv`: individual measurements and checks.
- `plan.csv`, `metadata.json`: crop coordinates, parameters, input/code hashes.
- `weights/`: exported training weights and quantized tables.
- `jobs/`: per-job results, specifications, serialized headers and logs.

Runtime and memory plots are not created. No reconstructed cubes, full trace CSV
files or compressed payload files are written. Payload hashes and bit counts are
saved for reproducibility. Replot without compression:

```bash
python tools/weight_init/weight_init_study.py --output results/fig421 --plot-only
```

## Workers, memory and validation

Each worker runs **one complete training or test compression**, with the original
serial predictor. Workers do not split a strip into independently initialized
pieces. Training runs complete before test jobs are scheduled. Worker count does
not change the scientific settings or averaging.

Default: two processes. CPU allocation and a conservative live RAM admission
check can reduce concurrency. `--total-memory-gb 90` and `--max-memory-gb 90`
are estimate budgets in GiB, not hard operating-system memory limits. The
predictor trace arrays are freed before entropy encoding. The sample-adaptive
reference encoder still uses its original internal arrays. Increasing workers
increases concurrent memory demand; it does not accelerate one compression.

Completed jobs are saved atomically. Resume requires the same input bytes, code,
geometry and parameters. You may change worker count and memory budgets. A
changed experiment needs a new output directory. Ctrl+C stops this script's
workers and leaves completed jobs available for resumption.

Checks include exact encoder-side lossless reconstruction, signed-Q table/header
round-trip, actual application of the requested initial weights, final weight
update arithmetic, and explicit table-bit accounting. See `VALIDATION.md` for
the execution checks performed. An independent decoder/conformance test suite
is not included.

Sources: CCSDS 120.2-G-2 section 4.2.6, printed pp. 4-21–4-23 and Annex C;
CCSDS 123.0-B-2 sections 4.6.3.3 and 4.10, and predictor header metadata.
